# Search Console 取数步骤

对应诊断链路的**环节 6（实际表现如何）**。这一环页面本身看不出来，
**只能从 Search Console 拿数据**。

> 这份文件写的是「怎么把数据弄出来」。拿到之后怎么读、怎么归因，见
> `gsc-analysis.md`。

---

## 前提与边界

| 项 | 说明 |
|---|---|
| **前提** | 用户的浏览器已登录 Google 账号，且该账号对这个 GSC 资源有访问权限 |
| **⚠️ 只读** | **只看、只导出。绝对不做任何写操作** —— 不提交 sitemap、不请求编入索引、不删除网址、不改设置。这些动作有真实后果且难以撤销 |
| **频率** | 别短时间反复点。一次把要的几个报表导完 |
| **拿不到就说拿不到** | 没权限、登录过期、界面找不到 —— 如实说，**不要猜数据**。这一环编造数字的危害比任何一环都大 |

---

## 一、进去

浏览器打开 `https://search.google.com/search-console`

如果账号下有多个资源，左上角的下拉框选对**资源**。注意区分：

| 资源类型 | 覆盖范围 |
|---|---|
| **网域**（`example.com`） | 所有子域名 + http/https 全都算 |
| **网址前缀**（`https://www.example.com/`） | **只算这个前缀**。`https://example.com/`（无 www）是另一个资源 |

选错资源会看到完全不同的数字。**报告里要写明用的是哪个资源。**

---

## 二、要导的四个报表

按优先级排。**不必每次全导**，看用户问的是什么。

### 1. 网页收录（Page indexing）⭐ 最重要

左侧菜单 →「索引」→「网页」

这是唯一能回答「**到底收录了多少、没收录的为什么**」的地方。

- 顶部两个数：**已编入索引** / **未编入索引**
- 下面「网页未编入索引的原因」是一张分类表 —— **这张表是整个环节 6 的核心**
- 点任一原因进去，能看到该原因下的具体 URL 清单，右上角可导出

**要导的**：那张原因分类表（每类的页面数），以及**你关心的那几类**的 URL 清单。

> 「未编入索引」里有几类**根本不是问题**（比如「网页会重定向」「有适当规范标记的
> 备用网页」）。**不要把总数当成问题数**，详见 `gsc-analysis.md`。

### 2. 效果（Performance）

左侧菜单 →「效果」→「搜索结果」

- 先把四个指标全部勾上：**点击次数 / 展示次数 / 点击率 / 平均排名**（默认只勾了前两个）
- 时间范围默认 3 个月，可拉到最长
- 下面六个标签页：查询 / 网页 / 国家/地区 / 设备 / 搜索外观 / 日期
- 右上角「导出」

**至少导「查询」和「网页」两个标签页。**

### 3. 站点地图（Sitemaps）

左侧菜单 →「索引」→「站点地图」

看每份 sitemap 的**提交状态**、**上次读取时间**、**已发现的网址数**。

这里能直接对上爬虫的结论：sitemap 提交了 2709 条、GSC 说发现了多少、
实际编入索引多少 —— 三个数一比，漏在哪一环一目了然。

### 4. 网址检查（URL Inspection）

顶部搜索框输入某个具体 URL。

**这是唯一能查单个 URL 真实状态的地方**：收录了没有、上次抓取时间、
Google 看到的规范网址是哪个、抓取时用的是哪个 Googlebot。

用在「这一页到底怎么回事」这种具体问题上。**它不能导出**，只能读页面。

## 三、导出

右上角「导出」按钮 → 三个选项：

| 选项 | 说明 |
|---|---|
| **下载 CSV** | 会下一个 **ZIP**，里面按标签页分成多个 CSV（`Queries.csv`、`Pages.csv`…） |
| 下载为 Google 表格 | 需要额外跳转，不推荐 |
| 下载为 Excel | `.xlsx`，读起来比 CSV 麻烦 |

**选 CSV。**

### 找到刚下的那个文件

下载完成后，文件在浏览器的默认下载目录。**按修改时间排序取最新的那个** ——
文件名通常形如 `<资源名>-Performance-on-Search-<日期>.zip`。

拿到 ZIP 后解压，里面的 CSV 直接读就行（UTF-8，带 BOM，第一行是表头）。

### 如果拿不到下载的文件

退而求其次，**直接读页面上的表格**（`snapshot` 或读渲染后的 DOM）。

⚠️ **这条路有明确的限制，用了就要在报告里写明**：

- 表格是**分页/虚拟滚动**的，一次可能只读到当前视口那几十行
- 只能拿到看得见的部分，**不能据此算总量或占比**
- 图表是 canvas，**读不出数值**

所以：读到多少就说多少，措辞写「**从界面上读到的前 N 行**」，
**绝不能**写成「全部数据显示……」。

## 四、界面改版了怎么办

Google 会改 GSC 的界面。上面的路径失效时：

1. 别硬找。左侧菜单的分组（索引 / 体验 / 效果 / 安全和手动操作）比较稳定
2. 找不到就问用户「你那边左侧菜单有哪几项」
3. **改完把这份文件里的路径一并更新** —— 这份文件单独存在就是为了让它好改

## 五、报告里必须写明的取数信息

拿到数据之后，报告开头要交代清楚，否则数字没法复核：

```
数据来源   Search Console · 资源 https://www.example.com/（网址前缀）
时间范围   2026-06-01 ~ 2026-08-31（3 个月）
取数方式   效果报告导出 CSV / 网页收录报告界面读取
取数时间   2026-09-02
```

**「取数方式」尤其要写** —— 导出的完整数据和界面上读的前几十行，
结论的可靠程度完全不同。
