# 语义化规则表

面向 `lib/check-page.js` 的语义化组，共 10 条。每条给出脚本判定条件、级别、报告文案与已知边界。

> **实现进度**：标题组 3 条（1~3）已实现，用例在 `tools/cases/heading-*.html`。
> 其余 7 条按图片组、链接组、地标组分批实现，每批跑一次 `npm run ruletest` 与 `npm run mutation`。

**这份表既是实现依据，也是报告文案的来源** —— 脚本只输出「命中了哪条规则 + 命中的证据」，报告里的「为什么」「怎么改」一律从本表查得，不由模型现编。这样同一条规则在 20 个页面上命中时，文案只占一份 token，且每次跑出来的措辞完全一致。

---

## 分级标准

| 级别 | 含义 | 处理 |
|---|---|---|
| **阻断** | 直接影响页面被收录或主题被识别，不改就会丢流量 | 上线前必须修 |
| **警告** | 搜索引擎能理解页面，但理解得不准或不完整 | 排期修 |
| **建议** | 最佳实践，改了更好，不改不致命 | 有空再说 |

---

## 脚本输出字段

```json
{
  "rule":     "h1-multiple",
  "group":    "语义化",
  "level":    "警告",
  "detail":   "页面中有 3 个 <h1>",
  "evidence": ["<h1 class=\"logo\">SourcingX</h1>", "<h1>产品列表</h1>", "…"],
  "count":    3
}
```

| 字段 | 说明 |
|---|---|
| `rule` | 规则 ID，对应本表的小节 |
| `group` | 固定 `语义化` |
| `level` | 从本表取，项目规范文件可覆盖 |
| `detail` | 脚本填的动态描述，带具体数字 |
| `evidence` | 命中元素的 HTML 片段，**每条截断到 120 字符，最多取 3 条**（防止把整页塞进上下文） |
| `count` | 命中总数，可能大于 `evidence` 长度 |

`why` / `howto` 不进脚本输出，报告生成时按 `rule` 从本表查。

## 1 · h1-missing

| | |
|---|---|
| **判定** | `$('h1').length === 0` |
| **级别** | 阻断 |
| **detail** | `页面中 <h1> 数量为 0` |
| **evidence** | 页面里的第一个 h2（如果有），用来提示"是不是本该是 h1" |

**为什么**：h1 是搜索引擎判断页面主题的最强信号之一。缺失时只能退回到 title 和正文去推断主题，识别准确度显著下降。

**怎么改**：在正文最顶部加一个 `<h1>`，写页面的核心主题。它和 title 表达同一件事，但不必逐字相同 —— title 是给搜索结果列表看的，h1 是给页面读者看的。

**边界**：CSS 隐藏的 h1（`display:none`）脚本判定不了，会被算作存在。这类页面拿到的是假通过。

---

## 2 · h1-multiple

| | |
|---|---|
| **判定** | `$('h1').length > 1` |
| **级别** | 警告 |
| **detail** | `页面中有 N 个 <h1>` |
| **evidence** | 前 3 个 h1 的完整标签，**并标注它落在哪个地标内**（如 `在 <nav> 内`） |

**为什么**：HTML5 规范允许每个 sectioning 元素里各有一个 h1，但搜索引擎的实际做法仍是「一页一个主题」。多个 h1 会稀释主题信号，让引擎不确定该以哪个为准。

**怎么改**：保留最能代表页面主题的那一个，其余降级为 h2 / h3。

**边界**：最常见的两个来源是「站点 logo 用了 h1」和「多个组件模板各自写了 h1」。`evidence` 一定要带上文本内容，人一眼就能看出是哪种。

落在 `nav` / `header` 里的 h1 **照报不误**，不做豁免 —— logo 用 h1 本身就是该改的问题，静默跳过等于把真问题藏起来。但证据里会标出它所在的地标，让人一眼分清是哪一类，优先级自己判断。这个祖先查询是换 cheerio 换来的能力，线性 token 流做不到。

⚠️ 证据截断时要**先给地标提示留出位置再截标题内容**。反过来的话，长标题会把提示挤掉，而那段提示正是用来区分两类来源的关键信息（用例 `heading-07`）。

## 3 · heading-skip

| | |
|---|---|
| **判定** | 按**文档顺序**取全部 `h1`~`h6`，逐对比较：`level[i] - level[i-1] > 1` |
| **级别** | 警告 |
| **detail** | `第 N 个标题「XXX」从 h2 直接跳到 h4` |
| **evidence** | 跳级处前后两个标题 |

**为什么**：标题层级就是页面的大纲。跳级会让搜索引擎和读屏软件无法还原章节的从属关系 —— h4 到底属于哪个 h2 说不清。

**怎么改**：把 h4 改成 h3；如果它确实不属于上一节，说明中间缺了一个 h3 小节标题，补上。

**边界**：**只查递增方向的跳级**。递减（h4 → h2）是正常的章节结束，不报。

---

## 4 · img-alt-missing

| | |
|---|---|
| **判定** | `$('img:not([alt])')` |
| **级别** | 警告 |
| **detail** | `N 张图片没有 alt 属性` |
| **evidence** | 前 3 张图的 `src`（截断到 120 字符） |

**为什么**：alt 是搜索引擎理解图片内容的唯一途径，也是图片搜索的收录依据。没有 alt 的图片，对爬虫来说等于不存在。

**怎么改**：给内容图写一句描述图里有什么；纯装饰图写 `alt=""`，明确声明「这是装饰，跳过它」。

**边界**：**`alt=""` 是合法写法，不报**。装饰图写空 alt 恰恰是规范做法，把它算作缺失是典型误报。

---

## 5 · img-alt-meaningless

| | |
|---|---|
| **判定** | alt 存在且非空，但命中下列任一模式（比较前 trim + 转小写） |
| **级别** | 建议 |
| **detail** | `N 张图片的 alt 没有描述内容` |
| **evidence** | 命中的 `alt` 原文 + 对应 `src` |

模式表：

| 模式 | 例子 |
|---|---|
| 就是文件名 | 结尾匹配 `\.(jpg\|jpeg\|png\|gif\|webp\|svg\|avif)$` |
| 占位词全等 | `image` `img` `photo` `picture` `banner` `icon` `logo` `placeholder` `untitled` `图片` `图` `照片` `图标` `横幅` `未命名` |
| 编号式 | `^(图\|图片\|image\|img\|photo\|pic)[\s_-]?\d+$`、`^(DSC\|IMG)[_-]?\d+$` |

**为什么**：这类 alt 和没写是等价的 —— 它描述的是文件本身，不是图里的内容。现成工具只查 alt 存不存在，查不出这一层。

**怎么改**：写图里实际有什么。「产品列表页顶部横幅」不如「三名工程师在展会上查看供应商样品」。

**边界**：本条只做词表匹配，能抓住明显的。**「alt 写了但和图不符」需要看图，属模型层，不在脚本范围**。词表允许项目规范文件追加。

## 6 · link-empty-href

| | |
|---|---|
| **判定** | `a` 标签的 href 为：属性不存在 / 空字符串 / `#` / `javascript:void(0)` / `javascript:;` |
| **级别** | 警告 |
| **detail** | `N 个 <a> 没有真实的跳转地址` |
| **evidence** | 前 3 个 a 标签，带文本 |

**为什么**：没有真实 href 的 a 不构成链接，爬虫不会跟进。页面之间的链接关系在这里断掉，目标页可能因为拿不到内链而始终不被发现。

**怎么改**：填真实 URL。如果这个交互本来就不是跳转（展开面板、打开弹窗），改用 `<button>` —— 用对标签，两边都清楚。

**边界**：**`href="#section-id"`（# 后面有内容）是合法的页内锚点，不报**。只有光秃秃的 `#` 才算。

---

## 7 · link-fake

| | |
|---|---|
| **判定** | `div` / `span` / `button` 带 `onclick` 属性，且 onclick 内容含 `location` `href` `open(` `push(` `navigate` `router` 之一 |
| **级别** | 警告 |
| **detail** | `N 处用非链接元素做跳转` |
| **evidence** | 前 3 处元素 |

**为什么**：爬虫只跟进 `a[href]`。用 JS 跳转的元素在爬虫眼里是死路，目标页拿不到任何内链，严重时整个分支都不会被发现。

**怎么改**：改成 `<a href="真实URL">`。SPA 里用框架的 Link 组件（`react-router` 的 `<Link>`、Next 的 `<Link>`），它们最终都渲染成带 href 的 a。

**边界**：⚠️ **本条召回率低，只作补充。** 它只能抓到写在 HTML 里的内联 `onclick`。React / Vue 通过 JSX `onClick` 或 `addEventListener` 绑定的事件，在服务端返回的 HTML 里完全看不到 —— 而这恰恰是现代前端的主流写法。**没报不等于没问题**，报告里要带上这句免责说明，否则会给人虚假的安全感。

---

## 8 · anchor-text-generic

| | |
|---|---|
| **判定** | a 标签的可见文本 trim 后全等于词表中的词（大小写不敏感） |
| **级别** | 建议 |
| **detail** | `N 个链接使用了无意义锚文本` |
| **evidence** | 锚文本 + href + `aria-label`（如果有） |

词表：`点击这里` `点这里` `这里` `更多` `了解更多` `查看更多` `阅读更多` `详情` `查看详情` `详细` `click here` `read more` `learn more` `more` `here` `link` `this page` `view more` `see more`

**为什么**：锚文本是搜索引擎判断**目标页**主题的重要依据。满屏「了解更多」等于把这个信号整体浪费掉 —— 目标页少了一次被正确归类的机会。

**怎么改**：把锚文本换成目标页的主题词。「了解更多」→「查看 2026 年供应商准入标准」。

**边界**：
- **全等匹配，不做包含匹配**。「了解更多关于供应商准入的信息」是好锚文本，包含匹配会把它误报掉。
- a 里只有一张图时，锚文本取该 img 的 `alt`，空 alt 的图片链接交给 `img-alt-missing` 管，本条不重复报。
- `aria-label` 写清楚了也仍然报 —— 搜索引擎主要看可见文本。但把它放进 evidence，方便人判断优先级。

## 9 · landmark-missing

| | |
|---|---|
| **判定** | `main` / `nav` / `header` / `footer` 四个标签，分别检查 `length === 0` |
| **级别** | 建议 |
| **detail** | `页面缺少地标标签：main、footer` |
| **evidence** | 无 |

**为什么**：这四个标签告诉解析器「哪块是正文、哪块是导航」。有了 `main`，搜索引擎提取正文时能更干净地排除页头页脚那些**每页都一样**的内容 —— 对模板化站点尤其重要，重复内容占比高会拉低整站质量评分。

**怎么改**：纯标签替换，不影响样式 —— 正文容器 `div` → `main`，导航 → `nav`，页头页尾 → `header` / `footer`。

**边界**：**只查这四个地标标签，不查「正文有没有包在 article 里」**。脚本判定不了正文在哪，硬查会大量误报（此为 M1 已确认的收敛项）。

## 10 · landmark-duplicate

| | |
|---|---|
| **判定** | `$('main').length > 1` |
| **级别** | 警告 |
| **detail** | `页面中有 N 个 <main>` |
| **evidence** | 前 3 个 main 的开标签 |

**为什么**：规范规定每页只能有一个可见的 `main`。出现多个，「正文在哪」这个信号就自相矛盾了，等于白标。

**怎么改**：只保留最外层那个 `main`，其余改成 `<section>` 或 `<div>`。

**边界**：**只查 main**。`nav` / `header` / `footer` 允许多个（顶部一个 nav、页脚一个 nav 很正常），不报。

## 已知盲区

写进报告，避免使用者误以为「没报就是没问题」：

| 盲区 | 影响的规则 | 原因 |
|---|---|---|
| 看不到 CSS | h1-missing | `display:none` 的 h1 被算作存在 |
| 看不到 JS 绑定的事件 | link-fake | 只能抓内联 `onclick`，React/Vue 的 onClick 抓不到 |
| 看不懂图片内容 | img-alt-meaningless | 只能查词表，查不出「alt 与图不符」 |
| 只看服务端 HTML | 全部 | 水合后才渲染的内容不在检查范围内 |

## 项目级覆盖

项目可在自己的 `seo-rules.md` 里调整，脚本读取后合并：

```yaml
overrides:
  h1-multiple: 建议        # 降级：本站 logo 就是用 h1，已知且不改
  anchor-text-generic: off # 关闭整条规则
extend:
  img-alt-meaningless:
    placeholder-words: [产品图, 主图, 默认图]
```

覆盖只能调 `level` 或关闭规则、往词表里追加词，**不能改判定逻辑** —— 判定逻辑改了，跨项目的报告就没法横向比较了。
