# 诊断链路

**这是这个 skill 的主线，其余清单都是它的明细。**

一个页面要从「存在」走到「有搜索流量」，中间有六道关。任何一道过不去，
后面的全部归零 —— 一个被 robots.txt 挡住的页面，title 写得再好也没人看得到。

```
1. 爬虫进得来吗        →  拿不到 URL，后面全免谈
2. 抓到的内容对吗      →  拿到了，但可能是个空壳
3. 允许被索引吗        →  看懂了，但页面自己说「别收录我」
4. 页面够不够格        →  允许收录，但没什么值得收的
5. 有路径被发现吗      →  值得收，但 Google 不知道它存在
6. 实际表现如何        →  收录了，有没有流量
```

## 每一环只有三种状态

**这条最容易做错，先说。**

| 状态 | 什么时候用 | 报告里写 |
|---|---|---|
| ✅ **通过** | 你**真的查了**，而且**看到了**说明它没问题的东西 | 「观察到：…」，附上看到的原始值 |
| ❌ **断了** | 查了，发现问题 | 「观察到：…」，附上原始值 |
| ⚠️ **证据不足** | 没查成、查不了、或者手上的信息不足以下判断 | 「无法判断：需要…才能确认」 |

### ⚠️ 「没发现问题」不等于「通过」

这是最容易犯的错，而且后果很严重 —— 用户看到绿灯就会去查别处，
真正的病因被绿灯盖住了。

**只有拿到了正面证据才能给通过。** 举例：

| 情形 | 正确状态 |
|---|---|
| 抓到了 robots.txt，逐条匹配后确认没挡住这个 URL | ✅ 通过 |
| robots.txt 返回 404 | ✅ 通过（404 等于全站放行，这是正面证据） |
| **robots.txt 没抓下来，不知道里面写了什么** | ⚠️ **证据不足**（不是通过！） |
| 看了响应头，里面没有 `X-Robots-Tag` | ✅ 通过 |
| **没看响应头** | ⚠️ **证据不足**（不是通过！） |

**一个环节里只要有一项是「证据不足」，整环就不能标通过** —— 标成「部分通过，
其中 X 项未能确认」，并把未确认的那项写进最后的「没查的、查不了的」。

### 工具拿不到数据时怎么办

**一个方法失败，换下一个，不要放弃也不要猜。** 按顺序试：

1. `web_fetch` / 内置抓取
2. 命令行直接请求（`curl -sSI` 看响应头、`curl -sS` 看正文）
3. 浏览器打开那个地址

`robots.txt`、`sitemap.xml` 都是**纯文本文件**，正常情况下三种方法里总有一种能拿到。

**都失败了就标「证据不足」，并如实说「用 A、B、C 三种方法都没取到」。**

> ⚠️ **绝对不要为失败编造原因。**
> 「推测该站做了 JS 反爬/动态渲染」这种话，在 robots.txt 上是**技术上不成立的** ——
> 它是一个静态文本文件，不经过任何 JS。编一个听起来合理的原因，比说「没取到」
> 危害大得多：用户会信，然后按一个不存在的问题去排查。
>
> 不知道为什么失败，就写「没取到，原因不明」。

## 怎么用这条链路

**顺着往下走，在第一个断掉的地方停下。** 那就是答案。

后面的环节**不用查** —— 不是省事，是查了也没意义：一个爬虫进不来的页面，
讨论它的 title 长度是浪费所有人的时间。报告里直接说明「环节 N 断了，
后面几环在这之前不具备讨论意义」。

反过来，**六环全通却没有流量**，那才轮到关键词、竞争度、内容质量这些更软的话题 ——
那些不在这个 skill 的范围内，如实说明。

## 从症状反查环节

用户带着症状来的时候，用这张表定位从哪一环开始查。
**GSC 那几个「未编入索引」的原因分类尤其值钱** —— 它们的措辞很像，指向的病因却完全不同。

| 用户说 / GSC 显示 | 大概率断在 | 为什么 |
|---|---|---|
| 「这页搜不到」 | 从 1 顺着查 | 症状太笼统，只能顺着走 |
| GSC：**被 robots.txt 屏蔽** | **环节 1** | 爬虫根本没进来 |
| GSC：**软 404** | **环节 2** | 抓到了，但内容看起来像空页/错误页 |
| GSC：**通过 noindex 标记排除** | **环节 3** | 页面自己拒绝 |
| GSC：**重复网页，未选定 canonical** | **环节 3** | canonical 配置问题，和入口无关 |
| GSC：**已抓取——尚未编入索引** | **环节 4** | ⚠️ **内容质量问题，建内链解决不了。** Google 抓了、看了、决定不收 |
| GSC：**已发现——尚未编入索引** | **环节 5** | ⚠️ **入口/内链问题。** Google 知道有这个 URL，但优先级太低一直没抓 |
| 「有曝光没点击」 | **环节 6** | 收录正常，是 title / description 不吸引人 |
| 「流量突然掉了」 | 先查 1、3 | 突发性下跌八成是配置被改了（robots、noindex、canonical），不是内容变差 |

> 「已抓取——尚未编入索引」和「已发现——尚未编入索引」只差一个字，
> **药完全不同**：前者要改内容，后者要建内链。搞反了会白干几个月。

## 环节 1 · 爬虫进得来吗

**问的是**：Googlebot 请求这个 URL，能不能拿到 200 和一份 HTML？

| 查什么 | 怎么查 | 证据等级 |
|---|---|---|
| robots.txt 有没有挡住 | 抓同源 `/robots.txt`，按 `rules-indexing.md` 的匹配算法判 | 直接观察 |
| HTTP 状态码 | 发一个 GET | 直接观察 |
| 重定向链 | 跟一遍。超过 5 跳 Google 会放弃 | 直接观察 |
| robots.txt 本身可达吗 | 5xx / 429 会让 Google **临时停抓全站** | 直接观察 |
| 有没有被 WAF / 人机验证挡住 | 换 Googlebot 的 User-Agent 再请求一次，对比结果 | 直接观察 |

**断在这里意味着**：这个页面对搜索引擎不存在。**优先级最高，别的都先放下。**

明细见 `rules-indexing.md` 第 3、4 条。

> ⚠️ **robots.txt 返回 404 是正常的**，等于全站放行，绝大多数站点就是这个状态。
> 把它当错误报是最常见的误报之一。

---

## 环节 2 · 抓到的内容对吗

**问的是**：服务端返回的那份 HTML 里，有没有真正的内容？

这一环专治 SPA。Googlebot 分两波：第一波只看**服务端 HTML**，
需要 JS 渲染的内容要排进渲染队列，**慢得多、优先级低、且不保证**。

| 查什么 | 怎么查 | 证据等级 |
|---|---|---|
| 服务端 HTML 里有没有正文 | 直接看抓到的 HTML，或看 `run.js` 输出的「统计」和「标题大纲」 | 直接观察 |
| meta 标签是不是客户端才塞的 | **用浏览器打开，对比渲染后 DOM 与服务端 HTML** | 直接观察 |
| 主要链接在不在服务端 HTML 里 | 数 `<a href>`。SPA 空壳通常个位数 | 直接观察 |
| 是不是软 404 | 内容为空/是错误提示，但状态码返回 200 | 直接观察 |

**断在这里意味着**：能抓到，但抓到的是个空壳。收录会**严重延迟或干脆不发生**。

### 这一环必须真的做对比，并把对比结果写出来

`run.js` 只看服务端 HTML，**它天然判不了这一环** —— 它看到的永远是第一波抓取
看到的那份，没有第二份可比。

**光看服务端 HTML 里「有 title、有 meta」就说「SSR 配置正确」是不成立的**：
meta 在服务端不代表正文和链接也在，很多站是 meta 走 SSR、内容走 CSR。

正确做法是拿到两份数据，逐项对比，**把这张表填出来**：

| 项 | 服务端 HTML | 渲染后 DOM | 一致？ |
|---|---|---|---|
| title | | | |
| h1 | | | |
| 正文字数（大致） | | | |
| `<a href>` 数量 | | | |
| ld+json 段数 | | | |

**链接数量这一项尤其要注意**：服务端只有 8 个链接、渲染后有 40 个 —— 这不是
「内链偏少」，是「**32 条内链要等 JS 渲染才存在**」，两个结论的含义天差地别。
只看服务端那个数就下「内链偏少」的判断是错的。

开了浏览器却不填这张表，等于这一环没查 —— 那就该标 ⚠️ 证据不足。

## 环节 3 · 允许被索引吗

**问的是**：有没有什么东西在主动说「别收录这页」？

| 查什么 | 明细 | 证据等级 |
|---|---|---|
| `<meta name="robots">` | `rules-indexing.md` 第 1 条 | 直接观察 |
| **`X-Robots-Tag` 响应头** | 第 2 条。⚠️ **源码里完全看不到**，来自 Nginx/CDN/网关 | 直接观察 |
| canonical 指向了别的页 | `rules-meta.md` 第 7 条 | 直接观察 |
| robots.txt 挡住 + 写了 noindex | 第 5 条。**两者互相抵消**，是经典反直觉错误 | 直接观察 |

**断在这里意味着**：抓到了、看懂了，但页面自己拒绝被收录。

这一环最容易出**隐形问题** —— `X-Robots-Tag` 不在代码里，前端全文搜 `noindex`
一无所获，往死里查前端代码，能卡好几天。

---

## 环节 4 · 页面够不够格

**问的是**：Google 抓了、也允许收，但这页有没有值得单独收录的内容？

对应 GSC 的「**已抓取——尚未编入索引**」—— Google 看过了，决定不收。

| 查什么 | 明细 | 证据等级 |
|---|---|---|
| title / description / h1 是否说清了这页是什么 | `rules-meta.md`、`rules-semantic.md` | 直接观察（有没有）＋ 推断（写得好不好） |
| 正文有多少实质内容 | 看「统计」和正文长度 | 直接观察 |
| **和同模板的其他页面是不是高度雷同** | 测 2~3 个同类页，对比 title / description / 正文结构 | **推断** |
| 结构化数据类型对不对得上页面 | `rules-schema.md` | 直接观察（有没有）＋ 推断（该不该有） |

**断在这里意味着**：这是**内容问题，不是技术问题**。建内链、改 meta 都救不了 ——
Google 已经看过内容并决定不收。

> ⚠️ 这一环最需要克制。「内容质量不够」是个很重的结论，**没有 GSC 数据佐证时
> 只能说「推断」**，不能说「这页因为内容质量没被收录」—— 你不知道它收没收。

---

## 环节 5 · 有路径被发现吗

**问的是**：Google 怎么知道这个 URL 存在？

对应 GSC 的「**已发现——尚未编入索引**」—— 知道有它，但一直排不上队去抓。

### 这一环有现成的工具，直接跑

```
node "<CUSTOM>/seo-doctor/run.js" --mode crawl --url "{站点首页}"
```

它模仿 Googlebot 第一波抓取：从首页 BFS，**只跟服务端 HTML 里的 `<a href>`**，
遵守 robots.txt，然后自动做三件事 ——

| 产出 | 回答什么 |
|---|---|
| 可达清单（含深度、来源页、锚文本、入链数） | 从首页点几次能到？谁在链它？ |
| **sitemap 差集** | 哪些页只在 sitemap 里、一条内链都没有 —— **这就是孤儿页** |
| 按规则聚合的批量体检 | 哪些问题是模板层的（命中 18/20 页 = 改一处修全站） |

顺带捞到两样单页检查看不见的东西：**死掉的内链**（内链指向 404）和
**指向重定向的内链**（浪费抓取预算）。

参数：`--max-pages 200`（总量封顶）`--max-depth 3`（点击深度）`--concurrency 3`。

### 但工具只看服务端 HTML —— 这三件事要你用浏览器补

爬虫不执行 JS，所以下面三种「JS 跳转」它一个都看不到，而它们恰恰是
现代前端最常见的写法：

| 查什么 | 怎么查 | 为什么要紧 |
|---|---|---|
| **按钮式跳转** | 页面上看起来像导航的 `<button>` / `<div>`，用浏览器**真的点一下**，看 URL 变不变 | URL 变了但元素不是 `<a href>` → 爬虫走不过去。首页那个「浏览全部产品」如果是 button，整个产品目录在 Googlebot 眼里就不存在 |
| **分页器** | 看分页容器里是不是真的 `<a href>`；拿不准就点「下一页」看 URL 变没变 | 博客 8 页 64 篇，分页器用 JS 跳 → **第 2 页往后的 56 篇全部不可达** |
| **列表项** | 列表页上每一项的点击目标 | 同上，决定整批详情页能不能被发现 |

具体判法和正确写法见 `rules-semantic.md` 的 `link-fake` 一条，那里有分页器的
正反例对照。

### 剩下的还要查

| 查什么 | 怎么查 | 证据等级 |
|---|---|---|
| sitemap 提交了没有、Google 读到没有 | Search Console 的「站点地图」报告 | 直接观察（需 GSC） |
| 锚文本有没有描述目标页 | 爬虫输出里每条链接都带锚文本 | 直接观察 |
| 入链薄弱的页面 | 爬虫的「内链结构」一节：只有 1 条入链且深度 ≥2 的 | 直接观察 |

**断在这里意味着**：页面本身没问题，是**没有路径**。

⚠️ 措辞要钉死：我们不执行 JS，**Googlebot 执行**。所以结论一律写
「**服务端 HTML 中不可达**」，绝不写「Google 爬不到」—— 两者不等价。

不过这个差异本身就是信息：链接在服务端 HTML 里 → 第一波抓取就能发现；
要等 JS 渲染才有 → 进第二波队列，慢得多。

## 环节 6 · 实际表现如何

**问的是**：收录了，有没有人搜到、点进来？

这一环**只能靠 Search Console 的导出数据**，页面本身看不出来。没有数据就如实说
「需要 GSC 数据才能回答」，**不要猜**。

| 数据 | 说明什么 |
|---|---|
| 高曝光低点击 | title / description 不吸引人（回到环节 4 改文案） |
| 排名 11~20 的查询 | 临门一脚，推一把就能上第一页的机会词 |
| 零曝光 | 选词有问题，不是页面质量问题 |
| 未收录原因分类 | 用上面那张「从症状反查环节」的表定位 |

---

## 证据分级：每条结论都要标

**这是这个工具能不能被信任的关键。** 三个等级，写报告时逐条标注：

| 等级 | 什么算 | 写法 |
|---|---|---|
| **直接观察** | 你真的请求了、看到了。「响应头里有 `X-Robots-Tag: noindex`」 | 「观察到：…」，附上原始值 |
| **合理推断** | 从观察到的现象推出来的。「3 个详情页都缺 canonical，推断是模板层问题」 | 「推断：…（依据：…）」，把依据写出来 |
| **证据不足** | 想知道但查不到。「这页实际收没收录，需要 GSC 数据」 | 「无法判断：需要…才能确认」 |

三条硬要求：

1. **绝不编造任何数据。** 没有的数字就是没有 —— 不要写「预计影响 60% 的页面」
   这种没有来源的推算，除非你真的测过并说明样本。
2. **推断必须写依据。** 「推断是模板层问题」后面一定跟「依据：测了 3 个详情页，
   都命中同一条」。没有依据的推断就是猜。
3. **证据不足要单独成段，不要藏起来。** 报告最后那段「没查的和查不了的」是必需的 ——
   省掉它，用户会以为全查过了。

## 发报告前的自查

写完先对着过一遍，**这几条都是真的犯过的错**：

| 自查 | 为什么 |
|---|---|
| **有没有把「没查」写成了结论？** 每个 ✅ 背后都要有一句「观察到：…」 | 「无 `X-Robots-Tag` 限制头 ✅」—— 但你根本没看响应头。这条给了假的安全感 |
| **盲区里列的东西，前面有没有已经下过结论？** 两处对照着读一遍 | 第三关写「无 X-Robots-Tag」、盲区写「未检测响应头级别指令」—— **自相矛盾**，读的人不知道该信哪句 |
| **每条「推断」后面有没有跟依据？** | 「推断：爬虫可正常访问」没有依据，就是猜 |
| **工具失败的地方，有没有编原因？** | 「推测该站做了 JS 反爬」—— robots.txt 是纯文本，这个解释技术上不成立 |
| **优先级有没有写理由？** 不能只贴「高 / 中 / 低」标签 | 排序的价值在理由里，光给个标签等于没排 |
| **有没有写出总评？** 「整体做得不错」「基础设置不错」都算 | 这是变相打分。要总览就给计数和「断在第几环」 |
| **各环的状态和「一环断了后面不用查」是否自洽？** | 如果标了环节 1 断，后面几环就不该还在逐条评点 |

## 输入与输出

| 用户能给什么 | 能查到哪几环 | 交付什么 |
|---|---|---|
| **一个 URL** | 1 ~ 4 | 单页诊断报告：断在哪一环、每条问题的「为什么 / 怎么改」、优先级排序 |
| **站点首页** | 1 ~ 5 | 加上：从首页可达的页面清单、模板层共性问题、孤儿页判断 |
| **一批同类 URL** | 1 ~ 4，且能判模板层 | 按规则聚合的报告（「`canonical-missing` 命中 18/20」）+ 模板层结论 |
| **GSC 导出的 CSV** | 6，并能反查 1~5 | 收录率与未收录原因分类、高曝光低点击页、机会词，以及**从数据反查到代码根因** |
| **代码 / 模板文件** | 定位到具体文件 | 指出该改哪个文件的哪一段（**不代写代码**，给文字说明） |

**不交付**：SEO 评分、关键词研究、外链分析、排名查询、修复代码。
这些要么需要付费数据源，要么不该由这个工具做。
