# Search Console 数据怎么读

对应诊断链路的**环节 6**。取数步骤见 `gsc-navigation.md`。

**这一环是整条链路唯一能反过来验证前五环的地方。** 前五环回答「有没有毛病」，
这一环回答「毛病有没有真的造成后果」—— 有些毛病 Google 根本不在乎，
有些没被前五环发现的问题在这里会露头。

---

## 一、未编入索引的 15 类原因 → 六环映射

**这张表是整个 GSC 分析的核心。** 类别名抄自 Google 官方文档。

⚠️ **先看最后一列：15 类里有 3 类根本不是问题。**
「未编入索引」这个总数里通常有一大半是正常状态，
**把总数当成问题数是这里最常见、也最浪费人力的误判。**

| GSC 里的原因 | 断在哪一环 | 怎么回事 / 该干什么 |
|---|---|---|
| **有适当规范标记的备用网页** | — | ✅ **正常，不是问题。** 这页正确地指向了它的规范网址，Google 收了规范的那个。分页、多语言版本、带参数的 URL 都会大量落在这里 |
| **网页会重定向** | — | ✅ **正常，不是问题。** 非规范 URL 重定向到规范 URL，本来就该这样 |
| **被 robots.txt 屏蔽** | **1** | 爬虫根本没进来。用 `rules-indexing.md` 的匹配算法找出是哪条规则挡的 |
| **服务器错误 (5xx)** | **1** | 抓取时服务器挂了。可能是偶发，也可能是 Googlebot 被限流 |
| **重定向错误** | **1** | 重定向链太长、成环、或链里有坏 URL |
| **未找到 (404)** | **1** | 这批 URL 不存在了。**关键是问：谁还在链它们？** 跑一次 `--mode crawl` 就知道有没有内链指向死页 |
| **被禁止访问 (403)** | **1** | 服务器拒绝了 Googlebot。常见成因是 WAF / 防爬规则误伤 |
| **因未经授权的请求 (401) 而被屏蔽** | **1** | 页面需要登录。如果不该需要，是权限配置错了 |
| **被其他 4xx 问题屏蔽** | **1** | 上面几类之外的 4xx |
| **软 404** | **2** | ⚠️ 返回 200 但内容看起来像「找不到」。**SPA 的重灾区** —— 路由没匹配上时渲染了空壳，状态码却是 200 |
| **通过 noindex 标记排除** | **3** | 页面自己说了别收。用 `rules-indexing.md` 查是 meta 还是 `X-Robots-Tag` |
| **重复网页，用户未选定规范网页** | **3** | 有内容重复的几个 URL，但没写 canonical，Google 自己挑了一个 |
| **重复网页，Google 选择的规范网页与用户指定的不同** | **3** | ⚠️ **你写了 canonical，Google 不认。** 说明 Google 认为你指的那页和这页内容不一致，或者那页质量更低 |
| **已抓取——尚未编入索引** | **4** | ⚠️ **内容问题。** Google 抓了、看了、决定不收。**建内链、改 meta 都救不了** |
| **已发现——尚未编入索引** | **5** | ⚠️ **入口/抓取预算问题。** Google 知道有这个 URL，但一直排不上队去抓 |

### 最后两条只差一个字，药完全不同

| | 已**发现**——尚未编入索引 | 已**抓取**——尚未编入索引 |
|---|---|---|
| Google 做了什么 | 知道有这个 URL，**还没去抓** | **抓了，看了，决定不收** |
| 病因 | 没有内链、抓取预算不够、优先级太低 | 内容太薄、和别的页面雷同、没有独立价值 |
| 药 | 建内链、加索引页、提高站点权重 | 改内容 |
| **搞反的后果** | 花几个月建内链，一页也没多收 | 花几个月改内容，问题其实是没人链它 |

**分不清这两个，是 SEO 项目最常见的方向性错误。** 报告里务必分开说。

## 二、和前五环交叉验证 ⭐ 这是这一环最值钱的部分

GSC 说「这批页有问题」，我们手上正好有工具去实测「问题出在哪一行代码」。
**把这两头接起来，就是从数据到根因的完整链路。**

| GSC 的结论 | 拿什么去验 | 验出来能说什么 |
|---|---|---|
| 大量「已发现——尚未编入索引」 | `--mode crawl` 跑一次，看这批 URL 在不在可达清单里 | 都是孤儿页 → **直接观察级别的证据**，不再是推断 |
| 大量「已抓取——尚未编入索引」 | 抽 3~5 个跑 `--mode check`，对比 title / description / 正文结构 | 高度雷同 → 模板化重复内容，是内容问题 |
| 「重复网页，未选定规范网页」 | 跑 `--mode check` 看 `canonical-missing` | 确认是没写还是写错 |
| 「Google 选的规范网页和你指定的不同」 | 跑 `--mode check` 看 canonical 指向哪，再去抓那一页对比内容 | 两页内容差多少，能解释 Google 为什么不认 |
| 「被 robots.txt 屏蔽」 | 按 `rules-indexing.md` 的匹配算法算一遍 | **指出是哪一条 Disallow 挡的** —— 这才是能直接改的东西 |
| 「软 404」 | 用浏览器打开，对比服务端 HTML 与渲染后 DOM | 是不是 SPA 路由没匹配上 |
| 「未找到 (404)」 | `--mode crawl` 看有没有内链指向它们 | 有内链 → 是站内死链，要修；没内链 → 是外部或历史 URL，可以不管 |

**没有这一步，GSC 分析就只是把数字念一遍。**

## 三、效果报告怎么读

先说清楚这四个指标的含义，不然会读歪：

| 指标 | 是什么 | 容易读错的地方 |
|---|---|---|
| **展示次数** | 你的页面在搜索结果里**出现过** | 出现在第 5 页也算展示。展示多不等于有人看见 |
| **点击次数** | 有人从搜索结果点进来 | — |
| **点击率** | 点击 ÷ 展示 | ⚠️ **品牌词的 CTR 天然极高**，混在一起算平均没有意义。要分开看 |
| **平均排名** | 图表里是「**全站最靠前结果**的平均位置」；表格里是**该行**的平均位置 | ⚠️ 两者不是一回事。而且一堆零星展示的长尾词会把这个数拉得很难看 |

### 值得单独捞出来的几类

| 现象 | 说明什么 | 该干什么 |
|---|---|---|
| **高展示、低点击**（展示多但 CTR 明显低于同批） | 排上去了，但标题/摘要没吸引力 | 回到环节 4 改 title / description。**这是投入产出比最高的一类** |
| **平均排名 11~20** | 卡在第一页外面，临门一脚 | 机会词。这批词对应的页面值得优先补内容和内链 |
| **有展示、零点击**且排名很靠后 | 词选得不对，或竞争太激烈 | 不是页面质量问题，别去改页面 |
| **完全没有展示的页面** | 收录了但从不出现 | 回到环节 4：这页在回答什么问题？有没有人搜这个？ |

### ⚠️ 报「高曝光低点击」之前先确认它真的收录了

一个页面**零展示**，可能是没收录（环节 1~5 的问题），
也可能是收录了但没人搜（环节 6 的问题）。**这两个原因的药完全不同。**

先去「网页收录」报表或用「网址检查」确认收录状态，再下结论。

## 四、五个数据陷阱

这几条不知道的话，算出来的数字会是错的：

### 1. 「未编入索引」的总数不是问题数

再说一遍，因为这是最常见的虚惊：「有适当规范标记的备用网页」和「网页会重定向」
**都是正常状态**，而且在有分页、多语言、带参数 URL 的站点上数量可能非常大。

**报告里要先把这两类剔掉，再谈「有多少页有问题」。**

### 2. 查询表的数字加起来对不上总数

Google 会隐藏**匿名查询**（太罕见、或可能含个人信息的搜索词）。
所以查询标签页里所有行的点击数加起来，**会小于**总点击数。

⚠️ **不要拿查询表算占比**（「这个词贡献了 30% 的点击」）——分母是不全的。
要算占比，用总数那一行。

### 3. 导出可能被截断

界面导出的表格有行数上限。**看一眼导出的行数：如果正好是个整数（比如 1000），
八成是被截断了**，结论只对这些行成立，措辞要写「导出的前 N 行中……」。

### 4. 数据有延迟，而且只保留 16 个月

- 最近两三天的数据不完整，**别用最新几天做对比**
- 历史数据只有 16 个月，**做同比要趁早导出留档**

### 5. 「流量下降」要看同比，不是环比

很多业务有明显的季节性和节假日效应。和上个月比会得出错误结论，
**和去年同期比**才看得出是不是真的掉了。

另外，**突发性的断崖下跌八成是配置被改了**（robots、noindex、canonical、
域名迁移），不是内容变差 —— 那种情况回到环节 1 和 3 去查，别在这里绕。

## 五、能下和不能下的结论

| 能说 | 不能说 |
|---|---|
| 「网页收录报告显示：已编入索引 120，未编入索引 2680，其中『已发现——尚未编入索引』2400」（**直接观察**，附截图或导出行数） | 「收录率只有 4%，说明网站质量差」——收录率低的原因有十几种，这是没有依据的归因 |
| 「这 2400 个 URL 里抽查 20 个，全部不在 `--mode crawl` 的可达清单中，推断是内链缺失导致（**依据**：抽样 20/20）」 | 「这 2400 个页面因为没有内链所以没被收录」——你只抽了 20 个，而且相关不等于因果 |
| 「查询表导出的前 1000 行中，平均排名 11~20 的有 37 个查询」 | 「全站有 37 个机会词」——导出被截断了，你不知道 1000 行之外还有多少 |
| 「无法判断：这批页面的收录状态需要逐个用网址检查确认，本次未做」 | 编一个数字 |

**这一环编造数字的危害比任何一环都大** —— 前五环的结论用户还能自己打开页面核对，
GSC 的数字他核对不了，只能信你。

## 六、一份 GSC 分析该有的结构

```
〇、取数信息        资源、时间范围、取数方式、取数时间（见 gsc-navigation.md 第五节）

一、收录概况        已编入索引 / 未编入索引，并**先剔除那两类正常状态**
                    真正有问题的是多少页

二、未收录原因归类   按第一节的映射表，每一类对应到哪一环
                    重点区分「已发现」和「已抓取」

三、交叉验证        对每一类占比大的原因，用 crawl / check 实测抽样
                    把「GSC 说有问题」变成「问题出在这一行」

四、搜索表现        高展示低点击的页、排名 11~20 的机会词
                    分品牌词和非品牌词看

五、先改哪几条      按诊断链路的优先级：断在越靠前的环节越优先，
                    模板层 > 单页，同等收益先做便宜的

六、没查的、查不了的  哪些数据没拿到、哪些结论只是抽样
```

第三段是这份分析和「把 GSC 数字念一遍」的全部区别。
